# 领域边界

贯通口袋公园资产、共建责任、巡检维修、开放状态和资金履约。

现有领域资料围绕以下边界组织：

- 公共空间档案
- 设施资产谱系
- 巡检与风险处置
- 共建履约资金
- 开放历史查询

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。

## 领域不变量（由 src/park_service.py 与测试锁定）

1. 档案（权属与移交、建设资金、设施、人群、巡检标准、养护责任、承诺、开放时段）
   以半开区间 `[valid_from, valid_to)` 版本化；新版本生效时旧版收口，历史版本不改写。
2. 每日先算单后巡检：按类别化周期生成应检任务、标记逾期；漏跑（含停机）补算；
   责任方按应检当日的责任版本快照进任务，移交不改变旧任务责任。
3. 巡检必须提交现场证据；风险结论自动产生高风险处置单。
4. 报修按相近度并入同一处置单，但报修记录按居民独立留痕，进度通知逐人生成，
   不允许以“已并单”为由让任何报修人失去进度。
5. 高风险只封闭受影响分区；同一分区不重复围挡；其余区域保持可用。
6. 维修完成不等于风险解除：必须由与维修人不同的人员复检；复检不过退回封闭返工；
   重新开放时刻不得早于复检通过时刻；重开同时撤围挡并结单。
7. 共建资金按确认工程量分段申请与审批，幂等键禁止重复支付；台账只追加。
8. 返工、撤销、质保追偿保留原付款行，另立负数调整行并回链原台账；
   养护移交不免除移交前承诺与质保责任，追偿对象仍为原企业。
9. 业务状态变更与居民通知在同一事务落库（事务发件箱），系统停机重启后：
   未落库操作整体不存在，已落库状态与待发通知都在，通知投递为至少一次。
10. 街道看板只读呈现当前可用区域、下一次巡检、未兑现承诺与资金占用；
    历史查询按日期复原封闭原因、接管方与已发通知，供争议时举证。
