# 口袋公园共建养护与开放治理

贯通口袋公园资产、共建责任、巡检维修、开放状态和资金履约。

## 参与方与事实

主要参与方包括街道管理人员、园林养护人员、共建企业、社区工作人员、居民。领域资料记录以下已经确认的事实：

- 山东利用拆违腾退用地、边角地和闲置地建设口袋公园
- 部分公园配置城市驿站、儿童设施、健身器材、照明及智慧设备
- 政企共建项目采用场地共建、养护共管、资源共享、成果共有机制

## 业务约束

- 地块移交
- 设施责任
- 风险分区
- 巡检周期
- 质保追偿
- 公众通知

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/park_context.py` 负责读取和校验这些资料。

## 共建养护服务

`src/park_service.py` 在领域资料之上提供可运行的共建养护服务：

- 地块权属与移交、建设资金、设施资产、适用人群、巡检标准、养护责任、企业共建承诺和开放时段，全部保存为带生效区间的记录
- 每天先计算应检项目与逾期责任，再接收巡检人员的现场证据；儿童设施、无障碍通道、夜间照明按各自周期巡检
- 相近报修汇入同一处置单，每位居民仍收到自己的进度通知
- 高风险只封闭受影响区域；维修完成后由另一名人员复检，重新开放不得早于风险解除
- 共建预算随确认工程量分段支付；返工、撤销和质保追偿保留原付款并另行调整；企业移交养护不带走此前责任
- 所有变化先写入追加式事件日志，临时围挡、待修设施和付款审批在系统停机重启后保持一致
- `park_overview` 向街道提供当前可用区域、下一次巡检、未兑现承诺和资金占用；`explain_as_of` 回到指定日期，说明当时为何封闭、由谁接管以及居民收到了什么通知

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。
